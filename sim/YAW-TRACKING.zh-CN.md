# Lite3 仿真角速度跟踪修复说明

## 问题与已确认原因

修复前，小的纯转向指令可能无法让机器人开始转向；较大的指令虽然能转动，实际角速度也不等于给定值。

2026-11-10 的原版对照确认：**当前部署锁定的官方 Lite3 策略与仿真执行模型组合，本身就存在低速转向不响应和转速偏差。Robonix 接入不是出现该现象的必要条件。** 该结论针对以下版本和本次测试工况，不推广到所有官方版本或真机：

- 官方部署库：`DeepRoboticsLab/Lite3_rl_deploy`，提交 `1c4a8f14c9c531903fa5a26783e3f9b99d1039d9`。
- 模型子模块：`deep_robotics_model`，提交 `b452a1f404d37155400242f18e454fed8bcc51b8`。

官方的速度输入不是一个能直接保证机身等速转动的执行器。实际链路为：

```text
归一化转向指令
  → RL 状态机读取指令
  → 策略输入乘以最大角速度 0.8 rad/s
  → ONNX 策略根据指令、机身状态、关节状态和上一动作生成关节目标角
  → 关节 PD 生成扭矩
  → MuJoCo 计算实际机身运动
```

因此，“给策略输入 0.08 rad/s”并不自动等于“机身实际转动 0.08 rad/s”。实测小指令下，关节目标几乎不随时间变化，机器人收敛到近似站立；较大指令才出现持续转向步态。这支持问题发生在官方策略与执行模型组合的解释，而不是 Robonix 或 Nav2 把小指令清零。

检查的官方命令路径没有发现显式的小角速度清零阈值；这里的“死区”描述的是实测响应，不能理解为已经找到源码中的某个 `if` 阈值。尚无训练过程、奖励函数或网络内部消融证据，**不能认定某个训练参数、ONNX 节点或摩擦参数是唯一根因**。

## 官方原版对照证据

从上述提交用 `git archive` 导出干净源码，独立编译 C++ 控制器，并运行官方 Python MuJoCo 仿真器。没有使用 Robonix、ROS/Nav2、本项目角速度补偿或工作目录中的 UDP 修补。仅关闭 GUI，并在原始状态发送之后以 50 Hz 只读记录物理状态。

- A 组：官方默认 `Lite3_stair.xml`，保留原始策略和控制/步进逻辑。
- B 组：同一控制器、策略和仿真器，仅替换为部署的 House187 场景/模型。
- 使用官方键盘接口：每次归一化步长 0.1，乘以最大角速度 0.8，按 1、3、6 次对应 0.08、0.24、0.48 rad/s。
- 正常站立并进入 RL 模式后，每项目标前停止 3 仿真秒；输入后稳定 12 仿真秒，再采样 12 仿真秒。各项目顺序执行，没有逐项重启。
- 实际角速度由展开后的机身 yaw 角增量除以仿真时间增量得到；姿态和高度检查均通过，没有将未进入 RL 或倒地误判为死区。

| 给定角速度（rad/s） | A：官方默认实际值 | B：House187 实际值 |
| ---: | ---: | ---: |
| +0.08 | +0.0000035 | +0.0000039 |
| +0.24 | +0.0003144 | +0.0003418 |
| +0.48 | +0.4266371 | +0.4299470 |
| -0.08 | -0.0000300 | -0.0000290 |
| -0.24 | -0.0000567 | -0.0000761 |
| -0.48 | -0.4380538 | -0.4387695 |

12 项测试的 RTF 为 0.999815–0.999825，约等于 1；因此本轮低速不响应不能用仿真时间比真实时间慢来解释。每个目标每方向测量一个窗口，未做跨启动重复性统计。

以 A 组为例，+0.08 rad/s 时关节目标的时间标准差平均约 0.0000063 rad，关节速度 RMS 约 0.000081 rad/s；+0.24 时关节目标标准差约 0.00044 rad。+0.48 时关节目标标准差约 0.1003 rad，出现持续步态。这是“小输入下策略输出基本维持站立”的观测依据。

House187 另有模型差异：场景的全局 `compiler boundinertia=0.001` 抬高了部分 HIP、SHANK、FOOT 连杆的惯量；机器人质量、关节顺序、阻尼、armature 和执行器参数一致。本轮两组转速接近，且 A 组已经复现问题，因此不能将 House187 惯量差异认定为全部原因。

原始物理状态、控制器日志、模型元数据、源码哈希及策略快照保存在测试 miniPC：`/home/bunny/cxk/lite3-official-comparison-20261110/evidence.tar.gz`。这是测试记录的位置，不是运行时依赖。

## 本次如何修复

本次没有重新训练或修改官方 ONNX 权重，而是在策略外增加角速度反馈控制，见 [yaw_velocity_controller.py](runtime/yaw_velocity_controller.py)，由 [lite3_bridge.py](runtime/lite3_bridge.py) 调用：

1. 将用户要求的角速度与 MuJoCo 实测机身角速度比较，通过起步前馈和反馈调整送给官方策略的转向输入，补偿近似死区及稳态偏差。
2. 在绝对值不超过 0.10 rad/s 的低速区使用累计转角误差控制间歇转向，抑制步态起动造成的过冲。
3. 对外目标限制为 ±0.50 rad/s，内部策略输入限制为 ±0.80 rad/s，并限制非零输出变化率和积分累积。
4. 零指令、超时、重置、暂停、离开 RL 或电机反馈过期时清空控制状态，避免残余积分重新触发转向。

`/lite3_sim/commanded_velocity` 表示接受的用户目标，`/lite3_sim/policy_velocity` 表示补偿后送给策略的输入。里程计、IMU 和查看器仍报告物理仿真状态，没有用目标速度覆盖实际速度。

验收检查的是稳定窗口内的平均 yaw 角速度，容差为 `max(0.003 rad/s, 目标绝对值的 5%)`；**不保证瞬时角速度始终等于目标，也不保证低速转向平滑**。低速补偿可能表现为间歇转动；反馈使用的是机体系角速度 z 分量，机身倾斜时与世界系 yaw 角速度存在差别。该补偿针对当前锁定策略和动力学调校，策略、模型、接触参数或控制时序改变后需要重新验收。

测试方法及命令见 [仿真说明的 Yaw-rate tracking](README.md#yaw-rate-tracking)。
